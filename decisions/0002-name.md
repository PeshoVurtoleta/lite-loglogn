## Context

`@zakkster/lite-loglogn` / `LogLogN.js` / `[lite-loglogn]` is the RECOMMENDED
name but was unconfirmed; the package is UNPUBLISHED (nothing on npm, only
RESEARCH.md + ROADMAP.md existed before this session). The name must be settled
before `git init` and scaffolding, because it stamps the main file name, the
error tag, all four package.json URLs, and every doc.

The scope is `@zakkster` (ONE `s`) -- CONFIRMED in the tree; a grep for the
extra-`s` misspelling of the scope returns nothing and must stay that way (the
blueprint caught that typo scope in a sibling roadmap, and it 404s on the
registry).

## Decision

**Confirm `@zakkster/lite-loglogn` / `LogLogN.js` / `[lite-loglogn]`.** It
parallels the sibling `@zakkster/lite-logn` / `LogN.js` exactly (the O(log log U)
sibling of the O(log n) package), so muscle memory and tooling carry over.

**Recommended resolution -- PENDING USER RATIFICATION at review.** The
recommendation is confirmed here on the record; the user ratifies it at review.

## Rejected name leans (ROADMAP section 0)

- **`lite-loglog`** -- drops the `n`, reads as "log of a log" with no
  data-structure connotation. Rejected.
- **`lite-log-log-n`** -- the npm hyphen-token discoverability problem: extra
  hyphens fragment the search token, the same reason `lite-logn` beat
  `lite-log-n`. Rejected.
